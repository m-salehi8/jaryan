# ۱۳. قابلیت‌ها و فیچرها

## ۱. Visual Workflow Builder

### توضیح
یک محیط بصری drag-and-drop برای طراحی فرایندهای سازمانی. بر اساس کتابخانه **ReactFlow** ساخته شده.

### انواع Node

| آیکون | نوع | کاربرد |
|-------|-----|--------|
| ⚡ | `trigger` | نقطه شروع فرایند |
| ✅ | `task` | وظیفه دستی قابل تکمیل |
| 👍 | `approval` | نیاز به تایید یا رد |
| 📋 | `form` | پر کردن فرم |
| 🔀 | `condition` | گیت تصمیم‌گیری (pass-through) |
| 🤖 | `ai_task` | پردازش خودکار AI |
| 📸 | `ocr_task` | استخراج OCR از تصویر |
| 🏁 | `end` | پایان فرایند |

### تنظیمات هر node
- **Assignee**: بر اساس نقش، کاربر خاص، مدیر، یا مدیر دپارتمان
- **Timeout**: مهلت زمانی + action (auto_reject / escalate)
- **Form**: اتصال به یک فرم
- **Dependencies**: وابستگی به node‌های دیگر (parallel)

### شرط لبه (Edge Condition)
لبه‌های بین node‌ها می‌توانند شرط داشته باشند:
- مقایسه فیلد فرم با مقدار (`amount > 5000000`)
- بررسی وضعیت تسک (`_task_status = approved`)
- ترکیب AND/OR

## ۲. Form Builder

### توضیح
یک ابزار Notion-style برای ساختن فرم‌های پویا بدون کد.

### انواع فیلد

| فیلد | کاربرد |
|------|--------|
| `text` | متن کوتاه |
| `textarea` | متن بلند |
| `number` | عدد |
| `date` | تاریخ |
| `select` | منوی کشویی |
| `checkbox` | چک‌باکس |
| `user` | انتخاب کاربر |
| `file` | آپلود فایل/تصویر |
| `heading` | عنوان (layout) |
| `divider` | جداکننده (layout) |
| `tabs` | سربرگ‌ها (container) |

### قابلیت‌های پیشرفته
- **Conditional Visibility**: نمایش/پنهان بر اساس مقدار فیلد دیگر
- **Tabs**: گروه‌بندی فیلدها در سربرگ
- **Validation**: min/max length، min/max value، regex pattern
- **Live Preview**: پیش‌نمایش real-time فرم
- **Field Permissions**: editable / readonly / hidden در هر مرحله فرایند

## ۳. AI Chat-to-Workflow

### توضیح
کاربر با زبان طبیعی فارسی توصیف می‌کند و AI یک workflow کامل با nodes و edges تولید می‌کند.

### جریان
```
کاربر: "یک فرایند درخواست مرخصی با تایید مدیر تیم بساز"

AI: "با توجه به درخواست شما، فرایند درخواست مرخصی را طراحی کردم.
این فرایند شامل ۴ مرحله است: شروع → تکمیل فرم توسط کارمند → 
تایید مدیر تیم → پایان.

```json
{
  "name": "فرایند درخواست مرخصی",
  ...
}
```

کاربر: دکمه "ذخیره و باز کردن در Builder" → workflow ایجاد می‌شود
```

### پشتیبانی از SSE
پاسخ AI به صورت streaming به کاربر نمایش داده می‌شود (مثل ChatGPT).

## ۴. AI Agent Node

### توضیح
یک node در فرایند که به صورت خودکار یک task را با AI انجام می‌دهد بدون دخالت انسان.

### مثال کاربردی
```
فرایند: ارزیابی خودکار درخواست خرید

Trigger → فرم درخواست → AI Agent (ارزیابی) → approval → end

AI Agent system prompt:
"تو یک ارزیاب درخواست خرید هستی. 
اگر مبلغ {{amount}} بیش از ۱۰ میلیون بود و دلیل {{reason}} 
معتبر است، تایید کن. JSON با کلیدهای approved, risk, comment برگردان."

خروجی AI در context:
{"approved": true, "risk": "low", "comment": "درخواست معتبر است"}

شرط لبه بعدی: ai_decision.approved = true
```

## ۵. OCR Node

### توضیح
استخراج خودکار اطلاعات از تصاویر (فاکتور، چک، سند) با Vision API.

### مثال
```
فرایند: ثبت فاکتور
Form (آپلود فاکتور) → OCR Node → تایید حسابداری

OCR Node:
- source_file_variable: {{invoice_file}}
- prompt: "تاریخ، مبلغ، فروشنده و آیتم‌ها را JSON بده"
- output_key: invoice_data

نتیجه در context:
{"date": "1403/04/15", "amount": 5500000, "vendor": "شرکت الف"}
```

## ۷. Process Monitoring

### توضیح
نظارت real-time بر تمام فرایندهای در حال اجرا.

### قابلیت‌ها
- لیست فرایندهای running/completed/rejected
- جزئیات کامل هر فرایند شامل تمام تسک‌ها
- **ProcessTimeline**: نمایش بصری گام به گام اجرا
- نشانگر SLA (نقطه قرمز برای فرایندهای دارای تسک دیرکرد)
- شاخص bottleneck (کندترین مرحله)

---

## ۸. Inbox (کارتابل)

### توضیح
مرکز مدیریت تسک‌های هر کاربر.

### قابلیت‌ها
- **Master/Detail**: لیست سمت راست + جزئیات کامل
- **فیلتر**: وضعیت، اولویت، نوع
- **فرم inline**: پر کردن فرم مستقیماً در کارتابل
- **SLA badges**: «دیرکرد» (قرمز) و «فوری» (زرد)
- **Draft**: ذخیره پیش‌نویس بدون submit
- **کامنت**: افزودن نظر به تسک

## ۱۴. SLA Management

### توضیح
نظارت خودکار بر مهلت زمانی تسک‌ها.

### هشدارهای بصری
| وضعیت | نمایش | شرط |
|-------|-------|-----|
| دیرکرد | badge قرمز | deadline گذشته |
| فوری | badge زرد | کمتر از ۲۴ ساعت تا deadline |
| عادی | — | بیش از ۲۴ ساعت تا deadline |

### Timeout خودکار
در `WorkflowBuilder` برای هر node قابل تنظیم:
- **auto_reject**: رد خودکار بعد از مهلت
- **escalate_to_manager**: ارجاع به مدیر
- **none**: بدون action

## ۱۵. Cron Workflows

### توضیح
فرایندهایی که به صورت زمان‌بندی شده و خودکار اجرا می‌شوند.

### استفاده
در `WorkflowBuilder`:
- `trigger_type = cron`
- `cron_expression = "0 9 * * 1"` (هر دوشنبه ساعت ۹)

### مثال Cron Expressions
```
0 9 * * 1-5    ← هر روز کاری ساعت ۹ صبح
0 * * * *      ← هر ساعت
0 0 1 * *      ← اول هر ماه
```
